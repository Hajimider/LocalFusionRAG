# 本地 RAG 知识库问答系统设计方案

## 1. 项目定位

项目面向无独立显卡、使用本地 CPU 的学习场景，目标是完成一个可解释的本地文档问答系统。系统不联网调用聊天接口，也不把微调作为第一阶段内容。7B GGUF 只负责生成，BGE-small 负责检索，FAISS 负责保存向量索引。

## 2. 技术架构

```text
文档目录 / 网页上传
        ↓
PDF、Markdown、TXT 解析
        ↓
递归文本切分
        ↓
BGE-small 向量化
        ↓
FAISS 本地索引
        ↓
问题向量检索 Top-K
        ↓
引用片段 + 问题组装提示词
        ↓
Qwen2.5 7B Instruct GGUF
        ↓
命令行或 FastAPI 流式回答
```

LangChain 只负责文档对象、文本切分和 FAISS 对接，模型调用通过 llama.cpp 完成，以便明确看到各个步骤。

## 3. 接口设计

- `GET /api/health`：检查服务、索引和模型配置状态。
- `POST /api/documents/upload`：上传 PDF、MD 或 TXT 文件，单文件限制 20 MB。
- `POST /api/index/build`：读取知识库目录并重建 FAISS 索引。
- `POST /api/chat/stream`：接收问题，返回 NDJSON 流；先返回来源，再逐段返回模型 token。
- `GET /docs`：使用 FastAPI 自动生成接口文档。

## 4. 可靠性设计

- 只允许指定文档后缀，上传文件名取 basename，避免路径穿越。
- 本地索引加载明确开启反序列化选项，但只加载本项目自己生成的索引。
- 检索距离超过阈值时不调用模型，直接提示知识库信息不足。
- llama.cpp 调用使用进程内锁，避免多个请求同时操作同一个 CPU 模型实例。
- 评测同时保存检索来源、RAG 回答和基础模型回答，便于定位问题是在检索还是生成阶段。

## 5. 验收标准

1. 三种文档能够成功建立索引。
2. 技术文档问题能够检索到预期来源，并在网页中展开查看片段。
3. 网页回答按流式方式显示，不需要等待完整文本生成后才看到内容。
4. 无关问题能够返回“知识库中没有足够信息”。
5. 自动评测报告能够保存检索命中率和两种回答的对照结果。
