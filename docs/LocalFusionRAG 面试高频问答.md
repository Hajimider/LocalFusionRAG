# 法律辅助混合 RAG 面试高频问答

## 一分钟介绍

我构建了一个面向中国大陆法律资料的本地混合 RAG 系统，支持 PDF、Markdown 和 TXT 法条/判例导入，通过 BGE 与 BM25 双路召回、RRF 融合、重排序和效力过滤定位依据，再由本地 GGUF 或兼容 API 生成带来源的辅助分析，并在资料不足时拒答。

## 高频问题与答案

### 1. 为什么法律场景要混合检索？

BM25 擅长法条编号、案号和专有词，向量检索擅长自然语言表述；两路融合能同时覆盖精确匹配和语义表达。

### 2. 如何避免把历史法当成现行法？

导入时记录 `validity`、生效/失效日期和适用地域，查询时支持只检索 `current`，回答 Prompt 还要求明确版本状态。

### 3. 判例来源展示哪些字段？

展示文件、法院、案号、裁判日期和原始来源链接，并把判例事实、理由与一般法条规则分开表述。

### 4. RRF 解决什么问题？

不同检索器的分数不可直接比较，RRF 按排名融合结果，减少单一路径漏召回。

### 5. CrossEncoder 不可用怎么办？

先回退到 BGE 向量二次排序，再回退到 RRF 原顺序，服务仍可用并报告实际后端。

### 6. 资料不足时如何控制幻觉？

只把检索片段传给模型，低置信度返回“知识库中没有足够信息”，并校验回答引用编号。

### 7. 为什么不自动爬取裁判文书？

部分站点有访问、版权和个人信息限制；项目采用用户下载或授权资料、本地解析和索引的合规边界。

### 8. 本地模型和 API 如何统一？

两者都实现统一的消息输入和流式输出接口，RAG Prompt、上下文长度和来源格式保持一致。

### 9. 如何验证检索效果？

使用带标准来源的固定问题集计算 Recall@K、MRR、NDCG@K、拒答准确率，并按法条/判例和难度分组分析。

### 10. 项目的局限是什么？

效果依赖资料覆盖和元数据质量，不能替代律师判断；正式使用前必须回到官方来源核对最新状态。

## 相关知识点

| 知识点 | 定义与作用 |
| --- | --- |
| RAG | 先检索外部资料再生成回答，降低模型脱离证据的风险。 |
| BM25 | 基于词频和逆文档频率的关键词检索，适合法条编号、案号等精确词。 |
| 向量检索 | 将问题和文档编码为向量，按语义相似度召回表达不同但含义接近的内容。 |
| RRF | 按各检索结果的名次进行融合，不依赖不同模型分数的同尺度。 |
| CrossEncoder | 对问题和候选片段成对打分，提升 Top-K 排序精度。 |
| 拒答 | 证据不足时主动停止生成，避免给出无依据的法律结论。 |
| 元数据过滤 | 按文档类型、效力状态、地域和日期缩小检索范围，减少版本混用。 |
| Recall@K / MRR / NDCG | 分别衡量前 K 是否召回、首个相关结果排名和整体排序质量。 |
