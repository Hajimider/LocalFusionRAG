# LocalFusionRAG 面试高频问答

## 一分钟项目介绍

我做了一个面向中文法律资料的混合 RAG 系统，主要解决关键词检索容易漏召回、法律版本容易混用以及大模型回答缺少依据的问题。系统解析了 3,183 份 DOCX，共约 1,664 万字符，切分为 40,781 个文本块，再通过 BGE 向量召回、BM25 关键词召回、RRF 融合和 CrossEncoder 重排序定位证据。生成侧支持法律意图路由、查询改写、来源引用和低置信度拒答，也可以在本地 Qwen2.5 GGUF 与兼容 API 之间切换。在 C-MTEB 固定公开子集上，混合检索加重排序取得 Hit@5 97.98%、MRR 79.83%。

## 高频问题与答案

### 1. 整个 RAG 链路是怎样的？

文档解析后按重叠窗口切分，由 BGE 生成向量并写入 FAISS，同时建立 BM25 索引。用户提问后先做意图判断和可选查询改写，再进行双路召回、RRF 融合、重排序、置信度判断，最后把证据交给大模型生成带引用的回答。

### 2. 为什么选择 RAG，而不是直接微调模型？

法律资料更新频繁，RAG 可以通过替换知识库更新内容，并能返回具体依据。微调更适合学习输出格式或行为习惯，不适合精确记忆大量会变化的法条。

### 3. 项目的法律语料是怎样处理的？

系统支持 DOCX、PDF、Markdown 和 TXT。实际解析 3,183 份 DOCX，提取约 1,664 万字符并切分为 40,781 个文本块，DOCX 保留来源、标题和法律类别，PDF 还会保留页码。

### 4. 为什么同时使用向量检索和 BM25？

向量检索擅长召回语义相近但措辞不同的内容，BM25 擅长法条名称、条款编号、案号和专有名词。两者结合能兼顾语义理解与精确匹配。

### 5. BGE、FAISS 分别负责什么？

BGE 是 Embedding 模型，负责把问题和文本编码为向量。FAISS 是向量索引，负责保存向量并快速查找距离最近的文本块。

### 6. 为什么使用 RRF，而不是直接相加两路分数？

向量距离和 BM25 分数不在同一尺度，直接相加需要额外归一化。RRF 只使用结果排名进行融合，对不同检索器的分数范围不敏感。

### 7. CrossEncoder 和向量召回有什么区别？

向量召回分别编码问题和文档，速度快，适合从大规模语料中筛选候选。CrossEncoder 联合编码问题与候选文本，排序更准但计算更慢，因此只处理召回后的少量结果。

### 8. CrossEncoder 加载失败时怎么办？

系统先回退到 BGE 向量相似度重排序，仍不可用时保留 RRF 排序，并在状态字段中返回实际使用的后端，避免重排序故障导致整个问答服务不可用。

### 9. 文本块为什么需要重叠？

重叠可以减少法条或语义跨越切分边界时的信息损失。重叠过大会增加重复召回和向量数量，因此需要结合检索评测选择块大小与重叠长度。

### 10. 查询改写和意图路由有什么作用？

查询改写把口语化问题整理成更适合检索的表达。意图路由区分法条检索、案件分析、法律对比和时间线等任务，再选择对应的检索条件与 Prompt。

### 11. 如何降低大模型幻觉？

只把召回证据传给模型，并要求回答引用 `[资料N]`。当检索置信度不足时直接拒答，模型超时、连接失败或重排序异常时返回明确的降级原因。

### 12. 拒答阈值是怎样确定的？

阈值只在 18 题校准集上选择，以平衡准确率为主，并列时优先拒答召回率。固定阈值后再评估 18 题独立测试集，取得 94.44% 准确率和 100% 拒答召回率，避免用测试集调参。

### 13. 检索效果是怎样评估的？

在 C-MTEB/T2Reranking 固定子集上使用 99 个查询和 1,591 篇候选文档，比较 Dense、BM25、Hybrid 和 Hybrid+Reranker 四组方案。最终方案取得 Hit@5 97.98%、MRR 79.83% 和 NDCG@5 63.74%。

### 14. 这些指标能代表法律问答效果吗？

不能完全代表。C-MTEB 固定子集用于验证通用检索和重排序链路，不是法律领域官方基准，也不评价最终生成答案；法律效果还需要带权威来源、版本标注和人工判分的领域评测集。

### 15. 如何保证索引构建过程可靠？

索引先写入新版本目录，完成 SHA-256 校验后再原子切换 `CURRENT` 指针，并使用进程内锁和文件锁避免并发覆盖。系统保留最近两个完整版本，构建失败不会破坏正在使用的索引。

### 16. 本地模型和 API 是怎样统一的？

两者使用同一套消息、Prompt、上下文和流式输出接口。本地模式通过 llama.cpp 加载 Qwen2.5 GGUF，API 模式调用 OpenAI 兼容接口，上层 RAG 链路不需要跟随模型来源变化。

### 17. 项目目前有哪些局限？

法律语料的效力状态和适用范围仍依赖可靠元数据，公开检索指标也不能代替法律领域评测。下一步应补充权威法律问答集、版本冲突检测、增量索引和生成答案人工评审。

## 相关知识点

| 知识点 | 定义 | 作用 |
| --- | --- | --- |
| RAG | 检索增强生成，先查外部知识再生成回答。 | 引入可更新证据，减少模型脱离资料作答。 |
| Embedding | 将文本映射为稠密向量。 | 计算问题与文档的语义相似度。 |
| BGE | 面向检索任务训练的文本向量模型系列。 | 为问题和文本块生成中文语义向量。 |
| FAISS | 高效的向量相似度搜索库。 | 保存向量并完成 Top-K 近邻召回。 |
| BM25 | 基于词频、逆文档频率和长度归一化的排序算法。 | 召回法条名、编号、案号等精确关键词。 |
| RRF | 按多个结果列表的排名进行倒数融合。 | 合并异构检索结果，避免直接比较不同分数。 |
| CrossEncoder | 联合编码问题和候选文本的相关性模型。 | 对初步召回结果进行更精细的二次排序。 |
| Query Rewrite | 将原问题改写为更适合检索的查询。 | 补全关键词并减少口语表达造成的漏召回。 |
| Intent Router | 根据问题类型选择处理链路。 | 为不同法律任务选择检索条件和 Prompt。 |
| Chunking | 把长文档切成可检索的文本块。 | 控制上下文粒度、向量数量和召回边界。 |
| Metadata Filter | 按类型、效力、地域或日期过滤文档。 | 缩小检索范围，减少法律版本混用。 |
| 拒答阈值 | 判断检索证据是否足够的分数边界。 | 证据不足时停止生成，降低无依据回答。 |
| Hit@K | 前 K 个结果中是否至少出现一个相关文档。 | 衡量查询能否在前 K 找到有效证据。 |
| MRR | 第一个相关结果排名倒数的平均值。 | 衡量相关结果是否排在靠前位置。 |
| NDCG@K | 考虑相关等级和排序位置的 Top-K 指标。 | 衡量整个结果列表的排序质量。 |
| GGUF / llama.cpp | GGUF 是量化模型格式，llama.cpp 是本地推理引擎。 | 在普通 CPU 环境运行 Qwen2.5 等本地模型。 |
| 流式生成 | 模型生成一段就立即返回一段。 | 降低用户等待首个回答片段的时间。 |
