## 1. 基础核心：Transformer底层

### 1.1 整体架构

编码器Encoder：双向注意力，适合理解类任务；解码器Decoder：单向自回归，大语言模型几乎全部用**Decoder‑Only架构**；Encoder‑Decoder：适合翻译（T5）。

### 1.2 核心组件

1. **自注意力 Self‑Attention** 公式： $$Attention(Q,K,V)=softmax(\frac{QK^T}{\sqrt{d_k}})V$$

- $Q$查询、$K$键、$V$值；$\sqrt{d_k}$缩放，防止维度大时内积爆炸softmax趋近0/1。
- **因果掩码（Causal Mask）**：Decoder‑Only关键，掩盖未来token，保证只能看上文，自回归生成。

1. **多头注意力 Multi‑Head Attention** 把QKV切分成多组头，并行做注意力，拼接输出；捕捉不同类型语义关系。
2. **RoPE 旋转位置编码（现在主流）**

- 代表：Llama、Qwen、DeepSeek
- 原理：对Q、K复数域旋转，位置信息嵌入query/key；支持**外推长度**，可超出训练上下文窗口。
- 对比：绝对位置编码（GPT1/2）、ALiBi（不编码位置，用偏置，Mistral）。

1. FFN前馈网络 标准：$FFN(x)=max(0,xW_1+b_1)W_2+b_2$ SwiGLU：主流大模型替换ReLU，激活分成两路门控，Llama2、Qwen全部使用，效果更好。
2. 层归一化

- Pre‑LN：现在全部大模型，归一化放在注意力/FFN输入；
- Post‑LN：原始论文，归一化在输出，训练不稳定。

### 1.3 关键变体

- **Grouped‑Query‑Attention GQA 分组查询注意力** KV分组共享，介于MHA（多头）和MQA（多查询）之间；**兼顾速度与效果**。Llama3、Qwen、DeepSeek‑V2都采用。
- **Sliding Window Attention 滑动窗口注意力** Mistral：只看最近N个token，降低显存，实现超长上下文。

## 2. 预训练大语言模型核心算法

### 2.1 预训练目标：自回归语言建模 LM

输入上文，预测下一个token，损失：交叉熵损失。 $$L_{LM}=-\sum logP(t_i|t_1,...,t_{i-1})$$

### 2.2 预训练流程

1. 大规模文本清洗、去重、过滤低质量数据
2. BPE字节对编码分词：把文本切分为子词token；中文模型会扩充中文词表（Qwen）
3. 大批量多卡训练：数据并行、张量并行、流水线并行、ZeRO优化显存占用
4. 学习率策略：余弦退火、warmup热身，之后衰减

### 2.3 关键训练优化

- **ZeRO**：把优化器、梯度、参数拆分到多张GPU，支持千亿大模型训练。
- 混合精度 FP16 / BF16：BF16更适合大模型，数值范围更大，不容易溢出，主流。

### 2.4 上下文窗口扩展技术

1. RoPE外推：直接推理超过训练长度，效果会下降；
2. YaRN：修正RoPE，提升长文本外推能力；
3. 滑动窗口；
4. Ring‑Attention环注意力：多卡分摊超长上下文KV缓存。

## 3. 对齐技术：让模型服从人类指令

> 预训练模型只是补全文本，对齐实现指令遵循、安全、对话能力。

### 3.1 SFT 监督微调 Supervised Fine‑Tuning

- 输入：高质量指令‑回答样本
- 做法：冻结部分/全量微调，继续交叉熵损失；
- 局限：只能学习样本，不能区分好坏，容易过拟合。

### 3.2 RLHF 基于人类反馈的强化学习

三阶段：

1. SFT；
2. 训练奖励模型RM：对同一个prompt多个回答，人工排序，训练RM输出打分；
3. PPO强化学习：用RM作为奖励，更新大模型，约束KL散度，防止模型偏离原始预训练。

**缺点**：训练链路复杂、不稳定、成本高。

### 3.3 RLAIF AI反馈替代人类

用强模型代替人工做排序标注，DeepSeek、Llama3大量使用，降低标注成本。

### 3.4 DPO 直接偏好优化【现在主流替代PPO】

> 无需单独训练RM，不需要PPO强化学习，直接使用偏好样本（好回答vs坏回答），一套损失直接微调LLM。

- 优势：实现简单、训练稳定、显存消耗低；Qwen、Llama3、Zephyr全部采用。
- 变种：IPO、KTO。

### 3.5 ORPO

把SFT损失和偏好损失合并成一步，单阶段对齐，进一步简化流程。

### 对齐常见问题

- 对齐税：对齐之后模型原始能力下降；
- 幻觉；
- 拒绝过度（安全对齐导致正常问题不回答）。

## 4. 推理加速算法（模型上线、本地部署）

### 4.1 KV Cache

最基础加速：缓存每一步的K、V，避免每一轮重新计算全部上文；推理显存大头就是KV缓存。

### 4.2 PagedAttention（vLLM核心）

分页式KV缓存，类似操作系统虚拟内存，解决KV碎片，大幅提升吞吐，vLLM引擎核心。

### 4.3 解码策略

1. Greedy Search贪心：每一步选概率最大token，容易重复。
2. Beam Search束搜索：保留top‑k候选序列，生成更通顺，速度慢。
3. Top‑P(Nucleus)：只累积概率超过P的候选，大模型对话默认。
4. Top‑K：采样只取概率最高K个token。
5. Temperature温度：>1增加随机性，<1让输出更确定。

### 4.4 推测解码 Speculative Decoding

小模型快速生成草稿，大模型校验，提升生成速度。

## 5. 量化&模型压缩算法

> 低显存本地运行模型，4bit/8bit量化

1. **GPTQ**：权重量化，后量化；主流，AWQ比GPTQ效果更好。
2. **AWQ**：激活感知权重量化，对重要权重保留精度，4bit损失更小。
3. GGUF/GGML：llama.cpp格式，CPU/GPU本地运行，Ollama底层格式。
4. SqueezeLLM；
5. FP8：英伟达新硬件原生支持，半量化，速度快。

> 4‑bit量化：权重4bit，激活保持BF16，是轻薄本本地运行主流方案。

微调侧量化：QLoRA，4bit基础模型上做LoRA微调，消费级显卡微调大模型。

### LoRA 低秩适配器

冻结主模型，只训练低秩矩阵A、B；参数量小，微调速度快；几乎所有开源模型二次微调都使用LoRA。 LoRA变体：DoRA，进一步提升LoRA效果。

## 7. LLM Agent 智能体算法&框架

### 核心概念

大模型作为思考中枢，调用工具、规划、记忆、反思。

1. **ReAct**：Thought → Action → Observation循环；思考+调用工具，最经典Agent范式。
2. CoT思维链 Chain‑of‑Thought：让模型分步思考，提升推理能力。
3. Self‑Consistency：多条CoT路径投票选答案。
4. ToT 思维树 Tree of Thought：多分支搜索，复杂问题。
5. Reflexion反思：根据错误反馈自我修正。

### Agent组件

- 规划：任务拆解
- 工具调用：Function‑call，JSON输出工具名参数
- 记忆：短期上下文窗口；长期向量数据库RAG检索增强
- RAG检索增强生成：文档分块‑向量化‑检索‑把参考文档喂给LLM生成，解决幻觉，知识库问答。

> RAG不等于Agent；RAG解决外部知识；Agent解决复杂任务规划+工具调用。

### 主流框架

LangChain、LlamaIndex、AutoGPT、OpenManus。

## 8. 主流开源大模型谱系&技术特点

### Llama系列(Meta)

- Llama2：RoPE，SwiGLU，Pre‑LN；GQA；
- Llama3：词表提升，更好多语言；Llama3.1支持128K上下文；

### Mistral(Mistral‑AI)

- Mistral‑7B：滑动窗口注意力；MQA；速度快；
- Mixtral‑8x7B：MoE混合专家模型，稀疏激活，参数量大，推理成本接近7B。

### MoE混合专家模型

- 原理：多个FFN专家，每次只激活部分专家；增大模型能力，但推理计算量不线性上涨。
- 代表：Mixtral、DeepSeek‑MoE、Qwen‑MoE。

### Qwen通义千问（阿里）

全系列开源，中文强；RoPE；GQA；Qwen2性能对标Llama3；支持多模态Qwen‑VL。

### DeepSeek（深度求索）

DeepSeek‑V2 GQA，超长上下文；数学代码能力强；开源MoE。

### 国产其他：InternLM、GLM‑4

GLM：GLM‑4使用Multi‑Query，GLM原始是自填充架构。

> 闭源参考：GPT‑4o，Claude，Gemini。

## 9. 损失函数与评估指标

### 损失

1. LM交叉熵损失（预训练、SFT）
2. RM损失（奖励模型排序损失）
3. DPO损失（偏好损失）
4. KL散度：RLHF约束，防止模型偏移

### 评估基准

- 通用能力：MMLU、CMMLU中文；
- 推理：GSM8K数学、MATH；
- 代码：HumanEval、MBPP；
- 长文本：LongBench；
- 中文：C‑Eval。

> 注意：基准分数高不等于实际对话体验好。
